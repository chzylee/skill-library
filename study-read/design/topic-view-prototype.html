At-least-once versus exactly-once trades throughput cost against duplicate-handling cost

judgment call source checked

Two sources answer this differently. The Kafka documentation presents transactions as the way to get exactly-once and notes a throughput cost without quantifying it. Confluent's guidance argues most pipelines should stay at-least-once and make consumers idempotent instead. Nothing states a rule for choosing between them.

“Exactly-once delivery requires cooperation with the destination storage system, but Kafka provides the offset which makes implementing this straightforward.”

A concept, tagged judgment call because two credible sources answer it differently and neither settles it. Not an edge case: there is no condition under which one is simply correct.
