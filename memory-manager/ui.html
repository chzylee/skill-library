What this is

Claude automatically remembers things about you from your work. Sometimes it remembers things it can't verify remain true, and you never see it. Wrong memories weaken your context.

This is where you can see it and fix it.

Questions

Where does Claude keep these notes?

One set per project folder — there's no single pile. A chat working in one project can't see another project's notes. This page shows all of them together.

Where are these on my computer?

They're ordinary text files. Each project gets a folder:

~/.claude/projects/<project>/memory/

Inside it: one .md file per note, plus MEMORY.md — the contents list Claude reads at the start of a chat. Deleted notes move to a .trash folder in the same place.

The .claude folder is hidden. In Finder, press ⌘⇧G and paste the path.

I fixed a note. Why doesn't my open chat notice?

A chat reads the notes once, when it starts. Fixing one here doesn't reach a conversation already running. Make your changes, close this page, then start a new chat. Claude gets a summary of what you changed either way.

Can I lose something?

Deleting moves a note to a trash folder — it isn't erased, and you can get it back. But nothing warns you later: if you delete something you needed, Claude simply stops knowing it. No error, no gap where it used to be.

Does any of this leave my computer?

No. It runs on your machine — no account, no network, nothing uploaded. This page is only reachable from this computer, and it closes when you're done.

What does "undated" mean?

The note doesn't say when it was written, so the date shown is the file's last-changed time. That's a guess about its age, not a record — which matters when you're deciding whether something is still true.

What's the panel at the top telling me?

Mismatches between your notes and the contents list Claude actually reads at the start of a chat — a note missing from the list, or a listing pointing at a note that's gone. Each one has a fix you approve. Nothing changes on its own.

Some notes are "filed under a folder that no longer exists"?

You renamed or moved that project. The notes stayed behind under the old name, where Claude never looks. Nothing is lost. Send them to the project's new location, or remove them if you don't want them.

What should I actually look at?

The ones marked project. Those are facts about the world — dates, plans, what you're working on — and they're what goes stale. A preference stays true; a date doesn't.

When would this be wrong?

It can show you what's remembered and roughly when it was written. It can't tell you whether any of it is still true — that judgment is yours. The trash folder also grows and nothing cleans it up.
