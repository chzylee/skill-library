memory-manager on GitHub

Why this exists

Claude writes notes about you as it works — your projects, your preferences, facts you've mentioned. They're useful, and they're invisible: you can't see them, and there's no built-in way to correct one.

The failure is quiet. A fact that was true when it was written keeps getting repeated after reality moves. Real example: an interview date changed, and sessions kept confidently stating the old one.

/memory-manager opens a page on your own computer showing every note Claude has written about you, grouped by project. You can read, edit, or delete any of them.

Getting started

How do I open it?

Just ask. Any of these work in Claude Code:

  • "What does Claude remember about me?" or "show me my memories"
  • "My memory about X is wrong" or "that's stale" — opens the page so you can fix or delete the note
  • "Audit my memory" — opens straight onto anything that needs your attention
  • /memory-manager — the direct command

A page opens in your browser. When you're done, click Finish & close — that reports what you changed back to Claude, which matters more than it sounds (see "If I fix a note…" below).

What will I see?

Every note, grouped by project, with a search box across all of them. Each note shows what kind of fact it holds and when it was written. Click one to read it in full, change any part of it, or delete it.

At the top there's a panel of things that need your judgment — bookkeeping mismatches the tool found but won't fix without your say-so. More on that below.

How Claude's memory works

Where does Claude keep these notes?

Each project folder has its own bundle of notes. There is no single global pile. A session working in one project can't see another project's notes — which is why this tool exists: it's the one view that shows everything, from every project, in one place.

If I fix a note, why doesn't the chat I have open notice?

When a Claude session starts, it doesn't read every note. It reads one contents page — a table of contents for that project's notes — and fetches individual notes later, as needed. That contents page is a snapshot: editing your notes does not change a session that's already running.

That's what Finish & close is for. It prints a summary of everything you changed, and Claude reads it — that's how the running session finds out.

If you've just corrected something important, start a fresh session afterward. A new session loads the corrected notes from scratch instead of relying on the summary.

Why do some dates say "inferred"?

Most notes don't record when they were written. For those, the tool falls back to the file's last-changed time and labels it inferred rather than declared. That matters because judging whether a fact has gone stale starts with knowing when it was written — and an inferred date is a guess that any program touching the file can accidentally reset.

Is there a limit to how much Claude remembers?

The contents page has a size limit, and the tool warns you when a project's page is getting close — you'll see numbers like "5/200 lines" next to each project. Worth knowing: the exact limit shown (200 lines / 25 KB) comes from the tool's own briefing and hasn't been independently confirmed, so treat it as a guide rather than a hard fact.

When a project moves or gets renamed

Why does it say some notes are filed under a folder that no longer exists?

A bundle of notes is labeled with the project folder's full location — the location is the label. Rename or move the project, and the notes stay put under the old label. Claude looks under the new location, finds nothing, and starts empty.

Nothing is deleted. The notes are intact, just filed under an address nobody visits anymore — like a folder labeled with your old home address after you move. This happens every time you rename or move a project, and nothing warns you when it does.

Should I re-home those notes or remove them?

Ask one question: does the project still exist?

  • Yes → Re-home. This relabels the notes to the project's new location — the tool guesses the right one for you, so usually you just confirm.
  • No, or the notes are stale → Remove. The notes go to a trash folder, so you can get them back.
  • Not sure → Leave it. It's harmless — the notes just sit there unread.

Safety

Does any of this leave my computer?

No. The page runs entirely on your own machine. Nothing is uploaded, there's no account, and no internet connection is used. The page can only be opened from your own computer, with a one-time key created fresh each run — another program or website can't reach it.

Can this delete something I need?

Two rules limit the damage you can do:

  • Nothing is ever truly deleted. "Delete" moves the note into a trash folder next to the others. If you regret it, the note is still on your computer.
  • Edits only change what you changed. Everything else in the note — including bookkeeping details you never see — is preserved exactly.

One honest caveat: if you delete a note and never restore it, Claude simply won't know that thing anymore — and nothing will tell you (see "When would this be wrong?"). When in doubt, edit instead of deleting.

Using it well

What is the panel at the top telling me?

The notes and their contents page are two separate things, and they can fall out of sync: the contents page can list a note that's gone, a note can exist without being listed (so Claude never sees it), the same note can be listed twice. Each row in that panel is one mismatch, described in plain terms, with a one-click fix.

Nothing is ever fixed automatically. The tool surfaces what it found and waits for you to rule on each one — the contents page contains judgment calls (what to call things, what order they go in) that a tool shouldn't overwrite on its own.

What should I actually do with this?

A five-minute pass, once in a while:

  • Skim the notes marked project first. Those record facts about the world — dates, plans, states of things — and they're the ones that go quietly wrong when reality moves. A preference stays true; a date doesn't.
  • Fix or delete anything that stopped being true. Edit if the note is mostly right; delete if it's beyond saving.
  • Deal with any orphaned bundles — re-home or remove, as above.
  • Click Finish & close, so the session you have open hears what changed.

The moment worth a pass is right after finishing or renaming a project — that's exactly when notes go stale and when bundles get orphaned.

When would this be wrong?

The tool shows you what's remembered and when it was written. It cannot tell you whether a remembered fact is still true — you're the one who judges whether reality has moved.

Other limits worth stating plainly:

  • The trash folder grows and nothing cleans it up. That's the price of "nothing is ever truly deleted" — the safety net is also clutter you'd have to clear yourself.
  • Deleting a note you needed produces no error. Claude just quietly stops knowing that thing. No session will ever flag the gap; it simply won't come up.
  • Most notes carry no written-on date, so the age shown is inferred from the file rather than declared — and an inferred date can be misleading about how stale a fact really is.
